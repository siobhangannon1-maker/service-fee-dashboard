## Scope and interpretation

The table covers every active-only route in the focused Xero/benchmark/import/financial-metadata set, including earlier Batch 1 Xero import endpoints and the production-report sync entry point. All started with `sensitiveApiAccess(route)`; existing lower-level/business validation remains. All 22 rows marked A now use `sensitiveApiAccess(route, ["admin", "super_admin"])` before queries, body processing or external calls. Both methods are protected where a route exposes two. Some GET handlers mutate the database: HTTP method alone does not imply a harmless read.

External column distinguishes remote reads/token acquisition from accounting mutations. No newly narrowed route directly creates a Xero invoice; the already Group A service-fee invoice route does and remains unchanged. “No intentional patient fields” is a source-code observation, not an assertion that arbitrary CSV/free-text/remote responses can never contain identifying data. No live data was inspected.

The previously permissive page/endpoint is not evidence of entitlement. Report mutation, destructive imports, account configuration and tenant/debug access meet the owner's explicit Group A criteria. No explicit conflicting non-Group-A caller was found for the 22 narrowed routes. Provider self-views, direct-table practice-manager report readers, signed payroll/continuation paths and service-role clients were not changed. Direct browser/table access is a separate security boundary: these API guards do not restrict an independent direct table query.

- GET /api/benchmarks and GET /api/billing-periods may remain active-user-only temporarily: fixed business definitions/calendar metadata, no patient data, no actual practice financial figures, no writes. Benchmark POST remains Group A and was not weakened.
